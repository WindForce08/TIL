- 물리 확인 (`./run.sh check`): 4 대 모두 집어 옮겨 세움. IK ↔ 시뮬 끝점 차이 0.13 mm, 손가락 −5.6 mm 에서 멈춤 (퍽 30 mm 에 맞음).
- 학습 (256 환경, 1500 반복, 약 21 분):
  - 1 차: 쥐기 · 들기는 배움 (걸음의 약 90 %), 성공 0 — 들고만 있어도 받는 보상이 성공 보너스보다 큼. 밀려남 판정 거리 설정 실수도 있었음.

## 11. 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| RViz2 에 로봇이 하얗게 보임 | 앞서 끈 launch 의 robot_state_publisher 가 남아 같은 도메인에 섞임 | 남은 프로세스를 PID 로 끄고, 이 폴더 launch 는 localhost 통신만 |
| Homing Offset 2048 이 무시됨 | 위치 모드는 ±1024 만 받음 | 그리퍼 기구를 다시 결합 (1550 / 2650) |
| 퍽을 쥐다 MOTOR_HW | 막힌 채 PWM 100 % 로 약 1.5 s | PWM 한계 400 + 펌웨어 GripGuard (실물 통과) |
| 펌웨어만 Lv2 로 옮기면 빌드 실패 | 시험용 가짜 Dynamixel 에 PWM 한계 항목이 없음 | 시험 · URDF 포함 12 개를 같이 옮김 |
| 위에서 잡기로는 퍽을 못 집음 | J4 상한 2.0 rad, 손가락이 URDF 끝점보다 21 mm 김 | 수평 잡기 · 퍽 25 ~ 33 cm |
| 학습 성공 0 | 1 차: 들고만 있는 보상이 큼 / 2 차: 0 ~ 15 mm 들기 보상 공백 | 보상 수정 방향 정리 (재학습 대기) |
| 업로드 전 모터 무응답 | 모터 12 V 전원 꺼짐 | 전원 켜고 OpenCR 리셋 → 부팅 검사 통과 |
| 영어로 된 실행 설명을 사용자가 거절 | 설명이 영어 | 실행 설명도 한글로 (기억에 남김) |
| dev 병합 충돌 7파일 | PR #10 이 같은 펌웨어를 고침 | 양쪽 유지, `WHEEL_GEAR 1.0` |
