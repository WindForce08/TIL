# 1. PID 실습 코드의 입력 방식

현재 PID 실습 코드의 `s` 명령은 **5개의 입력값**을 받는다.

```text
s <Kp> <Ki> <Kd> <speed_deg_s|max> <angle_deg>
```

예:

```text
s 3 0 0 20 90
```

각 입력값은 다음과 같다.

| 입력값 | 의미 | 단위 |
|---|---|---|
| `3` | Kp | 코드 정의에 따름 |
| `0` | Ki | 코드 정의에 따름 |
| `0` | Kd | 코드 정의에 따름 |
| `20` | 최대 속도 | °/s |
| `90` | 목표 각도 | ° |

개별적으로 설정한 다음 `s`로 실행하는 방식도 사용할 수 있다.

```text
k 3
i 0
d 0
v 20
a 90
s
```

# 2. PID 제어의 전체 흐름

PID는 한 번 계산하고 끝나는 것이 아니라 **현재 상태를 계속 측정하면서 오차를 줄이는 폐루프 제어**이다.

로봇 팔 관절을 `45°`로 움직이는 상황을 예로 들면:

```text
목표 각도
   ↓
45°
   ↓
현재 관절 각도 측정
   ↓
오차 계산
   ↓
PID 계산
   ↓
모터 속도 명령
   ↓
관절 움직임
   ↓
현재 각도 다시 측정
   ↓
오차 재계산
   ↺
```

PID의 핵심은 결국 다음 과정의 반복이다.

```text
목표와 현재의 차이
        ↓
      오차
        ↓
   제어량 계산
        ↓
    모터 움직임
        ↓
   현재 상태 변화
        ↓
      다시 측정
```

# 3. `error_deg`의 의미

현재 코드에서는 위치 오차를 다음과 같이 계산한다.

```cpp
error_rad = target_rad - position_rad;
```

즉:

```text
오차 = 목표 위치 - 현재 위치
```

이다.

예를 들어:

```text
목표 = 45°
현재 = 5°

error = 45 - 5
      = +40°
```

따라서 처음에 `error_deg = 40°`가 나오는 것은 정상이다.

목표와 현재 위치가 멀리 떨어져 있기 때문이다.

## 3.1 오차의 변화가 중요하다

목표가 `45°`라고 하면 정상적으로 목표에 접근하는 경우:

```text
45°
40°
30°
20°
10°
3°
1°
0°
```

처럼 오차가 줄어든다.

반대로:

```text
45°
44°
43°
42°
41°
40°
...
```

처럼 아주 천천히 줄어든다면 응답이 느린 것이다.

또 다른 경우:

```text
45°
30°
10°
-5°
8°
-4°
3°
-2°
...
```

처럼 오차의 부호가 반복해서 바뀐다면 목표를 지나쳤다가 다시 돌아오는 **진동**이 발생하고 있는 것이다.

따라서 PID 실습에서는 처음의 `error_deg` 값 하나보다 **시간에 따라 오차가 어떻게 변하는지**를 관찰해야 한다.

# 4. P / I / D가 실제 관절에서 하는 일

PID를 실제 로봇 관절에 연결하면 다음과 같이 이해할 수 있다.

| 항 | 생각하는 질문 | 실제 역할 |
|---|---|---|
| P | 지금 목표에서 얼마나 멀리 떨어져 있는가? | 현재 오차에 반응 |
| I | 오차가 계속 남아 있는가? | 지속적인 오차를 보정 |
| D | 지금 너무 빠르게 움직이고 있는가? | 움직임을 제동 |

간단하게 기억하면:

```text
Kp = 현재 오차에 대한 반응
Ki = 계속 남는 오차에 대한 보정
Kd = 너무 빠른 움직임에 대한 제동
```

---

# 5. Kp — 현재 오차에 대한 반응

## 5.1 기본 개념

P항은 현재 오차에 비례해서 제어 출력을 만든다.

```text
P 출력 = Kp × 현재 오차
```

예를 들어:

```text
목표 = 90°
현재 = 80°

오차 = 10°
```

Kp가 크면 같은 `10°`의 오차에도 더 강하게 반응한다.

## 5.2 실제 관절에서의 움직임

처음에:

```text
목표 = 90°
현재 = 0°
오차 = 90°
```

라면 목표에서 멀리 떨어져 있기 때문에 큰 출력이 발생한다.

관절이 움직여:

```text
현재 = 60°
오차 = 30°
```

가 되면 오차가 줄었으므로 P 출력도 줄어든다.

다시:

```text
현재 = 85°
오차 = 5°
```

가 되면 P 출력은 더 작아진다.

즉:

```text
목표에서 멀다
    ↓
큰 P 출력
    ↓
빠르게 접근

목표에 가까워진다
    ↓
P 출력 감소
    ↓
천천히 접근
```

## 5.3 Kp가 너무 작으면

```text
0°
↓
10°
↓
20°
↓
30°
↓
40°
↓
...
```

처럼 목표에 도달하기까지 시간이 오래 걸린다.

결과:

- 반응이 느림
- 목표까지 오래 걸림
- 외부 하중이나 마찰에 의해 오차가 남을 수 있음

## 5.4 Kp가 너무 크면

예:

```text
목표 = 90°

50°
↓
80°
↓
100°
```

목표를 지나치는 **오버슈트**가 발생할 수 있다.

그 후:

```text
100°
↓
80°
↓
95°
↓
87°
↓
92°
↓
...
```

처럼 목표 주변에서 반복해서 움직이면 진동이 발생한다.

따라서:

> Kp는 응답성을 높여주지만 너무 크면 오버슈트와 진동을 만들 수 있다.

# 6. Ki — 지속되는 오차의 보정

## 6.1 왜 I항이 필요한가?

목표가 `60°`인데 관절이 계속 `58°`에서 멈춘다고 하자.

```text
목표 = 60°
현재 = 58°

오차 = +2°
```

이 상태가 계속 유지된다면:

```text
시간       오차

0초        +2°
1초        +2°
2초        +2°
3초        +2°
4초        +2°
```

처럼 작은 오차가 계속 존재하게 된다.

이것을 **정상상태 오차(steady-state error)**라고 한다.

## 6.2 실제 상황으로 이해하기

로봇 팔이 물건을 들고 있다고 생각해보자.

목표 관절 위치가:

```text
60°
```

인데 팔에 무거운 물체가 달려 있어서 중력 때문에 관절이:

```text
58°
```

에서 더 이상 올라가지 않는다고 하자.

P 제어만 사용한다면:

```text
목표 = 60°
현재 = 58°
오차 = +2°
```

라는 작은 오차에 대해서만 제한적인 출력이 발생한다.

그 힘이 중력을 이기지 못하면:

```text
58°
58°
58°
58°
...
```

로 계속 남을 수 있다.

I항은 이 `+2°`의 오차가 계속 발생하는 것을 누적한다.

```text
작은 오차 발생
     ↓
오차가 계속 지속됨
     ↓
적분값 증가
     ↓
추가적인 제어 출력
     ↓
관절이 조금 더 이동
     ↓
58° → 59° → 60°
```

즉:

> **Ki는 "지금 오차가 얼마나 큰가?"보다 "작은 오차라도 계속 남아 있는가?"를 해결하는 데 중요하다.**

## 6.3 자동차 속도 예시

자동차가 오르막을 올라간다고 생각할 수도 있다.

목표 속도:

```text
50 km/h
```

현재 속도:

```text
48 km/h
```

이면:

```text
오차 = +2 km/h
```

이다.

오르막 때문에 계속 `48 km/h`에 머문다면 I항이 이 오차를 계속 누적한다.

```text
48 → 48 → 48 → 48 → ...
```

↓

```text
"2 km/h 부족한 상태가 계속되고 있다."
```

↓

추가 출력 발생

↓

```text
48 → 49 → 50 km/h
```

이런 방식으로 지속적인 오차를 보정한다.

## 6.4 Ki가 너무 크면

적분값이 지나치게 많이 쌓이면 목표에 도달한 이후에도 같은 방향으로 출력이 계속 발생할 수 있다.

예:

```text
목표 = 60°

50°
↓
55°
↓
58°
↓
62°
```

목표를 지나친 뒤에도 적분값 때문에 계속 출력이 남으면:

```text
62°
↓
57°
↓
63°
↓
58°
↓
62°
...
```

처럼 진동할 수 있다.

따라서 PID 튜닝 초기에는:

```text
Ki = 0
```

으로 시작하는 것이 좋다.

# 7. Kd — 너무 빠른 움직임의 제동

일반적인 PID에서 D항은 오차의 변화 속도를 이용한다.

하지만 현재 실습 코드에서는 **오차의 미분값 대신 측정된 모터 속도**를 사용한다.

```cpp
d_term = -kd * measured_speed_rad_s;
```

따라서 현재 코드에서는:

```text
D항 = -Kd × 측정된 모터 속도
```

로 이해할 수 있다.

## 7.1 실제 관절에서의 의미

목표가 `90°`이고 현재가 `50°`라면:

```text
오차 = +40°
```

이다.

관절이 목표를 향해 빠르게 움직여:

```text
50°
↓
70°
↓
85°
↓
95°
```

처럼 움직이면 목표에 도달하기 전에 속도를 줄일 필요가 있다.

이때 D항이 제동 역할을 한다.

```text
빠르게 접근
    ↓
D항 작동
    ↓
제동
    ↓
목표 근처에서 감속
```

자동차의 브레이크와 비슷하게 생각할 수 있다.

## 7.2 Kd가 너무 작으면

```text
50°
↓
80°
↓
95°
↓
85°
↓
93°
↓
...
```

처럼 목표를 지나치는 현상이 커질 수 있다.

## 7.3 Kd가 너무 크면

반대로 제동을 너무 강하게 하면:

```text
50°
↓
60°
↓
68°
↓
74°
↓
...
```

처럼 움직임이 지나치게 억제될 수 있다.

즉:

```text
Kd가 너무 작음 → 오버슈트 / 진동 가능

Kd가 너무 큼 → 움직임이 둔해짐
```

# 8. 실제 코드의 단위와 PID 식

현재 실습에서 가장 중요한 부분 중 하나는 **각도와 속도의 단위가 서로 다르다는 것**이다.

## 8.1 단위 정리

```text
사용자 목표 각도
        ↓
       °

PID 내부 목표 위치
        ↓
       rad

PID 내부 현재 위치
        ↓
       rad

PID 내부 위치 오차
        ↓
       rad

측정된 모터 속도
        ↓
      rad/s

최종 속도 명령
        ↓
       °/s
```

| 변수 | 의미 | 단위 |
|---|---|---|
| `target_deg` | 목표 각도 | ° |
| `position_deg` | 현재 각도 | ° |
| `target_rad` | 내부 목표 각도 | rad |
| `position_rad` | 내부 현재 각도 | rad |
| `error_rad` | 목표 - 현재 | rad |
| `measured_speed_rad_s` | 측정 모터 속도 | rad/s |
| `u_deg_s` | 최종 속도 명령 | °/s |

## 8.2 위치 오차

현재 코드:

```cpp
error_rad = target_rad - position_rad;
```

즉:

```text
error_rad = 목표 위치(rad) - 현재 위치(rad)
```

이다.

예를 들어:

```text
목표 = 45°
현재 = 5°
```

이면 사람이 보기에는:

```text
error = +40°
```

이지만 PID 내부에서는 rad 단위로 계산한다.

## 8.3 P항

```text
P = Kp × error_rad
```

P항은 `error_rad`를 사용한다.

즉 현재 관절이 목표에서 얼마나 떨어져 있는지를 이용한다.

## 8.4 I항

```text
I = Ki × 누적된 error_rad
```

시간이 지나면서 발생한 오차를 누적한다.

따라서 작은 오차라도 오랫동안 지속되면 I항이 점점 커질 수 있다.

## 8.5 D항

현재 코드:

```cpp
d_term = -kd * measured_speed_rad_s;
```

즉:

```text
D = -Kd × 측정 모터 속도(rad/s)
```

이다.

**중요:** 현재 코드의 D항은 일반적인 교과서 PID에서처럼 단순히 `error`를 미분하는 형태가 아니다.

현재 코드에서는 **실제 측정된 모터 속도를 이용해 제동**한다.

# 9. PID 게인과 Ti / Td의 차이

PID를 공부할 때 `Ki`, `Kd`와 `Ti`, `Td`를 혼동하기 쉽다.

## 9.1 직접 게인 방식

코드에서 흔히 볼 수 있는 형태:

```text
PID 출력 =
Kp × 현재 오차
+ Ki × 누적 오차
+ Kd × 오차 변화
```

여기서:

```text
Kp = 비례 게인
Ki = 적분 게인
Kd = 미분 게인
```

이다.

## 9.2 시간 파라미터 방식

Ziegler–Nichols에서는 다음과 같이:

```text
Kp
Ti
Td
```

를 사용하는 형태가 많이 나온다.

여기서:

```text
Kp = 비례 게인
Ti = 적분 시간
Td = 미분 시간
```

이다.

`Ti`와 `Td`는 게인이 아니라 **시간을 나타내는 파라미터**이다.

두 표현 사이의 관계는:

```text
Ki = Kp / Ti

Kd = Kp × Td
```

이다.

따라서 Ziegler–Nichols에서 `Ti`, `Td`를 계산했다고 해서 그것을 그대로 `Ki`, `Kd` 자리에 넣으면 안 된다.

---

# 10. PID 튜닝의 기본 순서

PID를 튜닝할 때 처음부터 세 값을 동시에 변경하면 어떤 값 때문에 시스템이 변했는지 알기 어렵다.

따라서 기본적으로 하나씩 확인한다.

```text
① Ki = 0
   Kd = 0

        ↓

② Kp를 조금씩 증가

        ↓

③ 응답속도 확인

        ↓

④ 오버슈트 / 진동 확인

        ↓

⑤ Ki 추가

        ↓

⑥ 정상상태 오차 확인

        ↓

⑦ Kd 추가

        ↓

⑧ 오버슈트와 진동 확인
```

실습에서는 각 게인의 영향을 하나씩 확인하는 것이 중요하다.

---

# 11. 지글러–니콜스(Ziegler–Nichols) 튜닝법

지글러–니콜스 폐루프 튜닝법은 **P 제어만 사용하는 상태에서 Kp를 증가시키며 시스템의 한계 상태를 찾는 방법**이다.

처음에는:

```text
Ki = 0
Kd = 0
```

으로 설정한다.

그다음 Kp를 조금씩 증가시킨다.

```text
Kp 증가
   ↓
응답성 증가
   ↓
오버슈트 증가
   ↓
진동 발생
   ↓
지속적인 진동
```

이때 시스템의 한계 상태를 이용하여 PID 초기값을 계산한다.

---

# 12. `Ku` — Ultimate Gain

`Ku`는 **Ultimate Gain**, 즉 한계 이득이다.

Kp를 증가시키다가 시스템이 감쇠되지 않고 지속적으로 진동하는 지점의 Kp를 `Ku`라고 한다.

개념적으로:

```text
목표
──────────────────────

      /\      /\      /\
     /  \    /  \    /  \
────/────\──/────\──/────\──
```

이때:

```text
Ku = 지속적인 진동이 발생하는 Kp
```

이다.

---

# 13. `Tu` — Ultimate Period

`Tu`는 **Ultimate Period**, 즉 한계 주기이다.

`Ku` 상태에서 발생하는 지속적인 진동의 한 주기를 측정한다.

일반적으로 첫 번째 peak에서 다음 peak까지의 시간을 사용한다.

예:

```text
첫 번째 peak = 1.2초
두 번째 peak = 2.0초

Tu = 0.8초
```

따라서:

```text
Ku = 50
Tu = 0.8 sec
```

처럼 기록한다.

---

# 14. Ziegler–Nichols 튜닝 공식

## P 제어

```text
Kp = 0.5 × Ku
```

## PI 제어

```text
Kp = 0.45 × Ku
Ti = Tu / 1.2
```

## PID 제어

```text
Kp = 0.6 × Ku
Ti = Tu / 2
Td = Tu / 8
```

---

# 15. Ziegler–Nichols 결과를 실제 코드의 게인으로 변환하기

예를 들어:

```text
Ku = 40
Tu = 0.6 sec
```

이라고 하자.

먼저 Ziegler–Nichols PID 값을 계산한다.

```text
Kp = 0.6 × 40
   = 24

Ti = 0.6 / 2
   = 0.3 sec

Td = 0.6 / 8
   = 0.075 sec
```

따라서:

```text
Kp = 24
Ti = 0.3 sec
Td = 0.075 sec
```

이다.

실제 코드가 `Kp`, `Ki`, `Kd`를 요구한다면:

```text
Ki = Kp / Ti
   = 24 / 0.3
   = 80

Kd = Kp × Td
   = 24 × 0.075
   = 1.8
```

따라서:

```text
Kp = 24
Ki = 80
Kd = 1.8
```

로 변환할 수 있다.

현재 코드의 입력 형식이라면:

```text
s 24 80 1.8 20 45
```

와 같은 형태가 된다.

단, 이것은 **현재 코드의 `Ki`, `Kd` 정의가 표준적인 PID 게인 정의와 동일한 경우**에 해당한다.

특히 현재 코드의 D항은:

```cpp
d_term = -kd * measured_speed_rad_s;
```

형태이므로, Ziegler–Nichols에서 계산한 값을 실제 코드에 적용할 때는 **코드의 PID 계산식과 단위를 최종적으로 확인해야 한다.**

---

# 16. 로봇 관절에 적용할 때의 주의사항

지글러–니콜스는 시스템을 지속적인 진동 상태까지 접근시키기 때문에 실제 로봇에서는 주의해야 한다.

```text
Kp 증가
   ↓
오버슈트
   ↓
진동
   ↓
지속적인 진동
   ↓
Ku 측정
   ↓
Tu 측정
```

실제 관절에서는:

- 관절이 크게 흔들릴 수 있음
- 모터에 큰 부하가 걸릴 수 있음
- 감속기에 충격이 발생할 수 있음
- 기계 구조물에 진동이 전달될 수 있음

따라서 작은 값부터 단계적으로 증가시키는 것이 중요하다.

---

# 17. 실습에서 관찰해야 할 값

현재 실습에서는 다음 값들을 특히 중요하게 관찰한다.

```text
position_deg
error_deg
u_deg_s
```

이 세 값은 다음과 같이 연결된다.

```text
목표각도
   ↓
error_deg
   ↓
PID 계산
   ↓
u_deg_s
   ↓
모터
   ↓
position_deg
   ↓
error_deg 재계산
```

## 17.1 `position_deg`

실제 관절의 현재 위치이다.

목표가 `45°`라면:

```text
0°
↓
10°
↓
20°
↓
30°
↓
40°
↓
45°
```

와 같이 움직이는지 확인한다.

## 17.2 `error_deg`

목표와 현재 위치의 차이이다.

목표가 `45°`라면:

| 현재 위치 | error |
|---:|---:|
| 0° | +45° |
| 20° | +25° |
| 40° | +5° |
| 44° | +1° |
| 45° | 0° |
| 50° | -5° |

목표를 지나치면 오차의 부호가 반대로 바뀐다.

```text
목표 = 45°

현재 = 40°
error = +5°

현재 = 50°
error = -5°
```

따라서 `error_deg`의 부호 변화를 통해 목표를 지나쳤는지 확인할 수 있다.

## 17.3 `u_deg_s`

PID가 계산한 최종 속도 명령이다.

예:

```text
error = +20°
```

이면 목표 방향으로 움직이라는 명령이 발생한다.

반대로:

```text
error = -5°
```

이면 반대 방향으로 움직이게 된다.

최종적으로:

```text
error
  ↓
PID
  ↓
u_deg_s
  ↓
모터
  ↓
position
  ↓
error
```

의 관계를 실제 데이터에서 확인하는 것이 중요하다.

# 18. 최종 정리

## 18.1 PID 각 항의 역할

```text
Kp
│
└─ 현재 오차에 즉시 반응
   └─ 너무 크면 오버슈트 / 진동


Ki
│
└─ 지속되는 오차를 누적하여 보정
   └─ 정상상태 오차 제거
   └─ 너무 크면 오버슈트 / 진동


Kd
│
└─ 빠른 움직임을 제동
   └─ 오버슈트 / 진동 감소
   └─ 너무 크면 움직임이 둔해짐
```

## 18.2 실제 코드의 단위

```text
사용자 입력 각도
    ↓
°

PID 내부 위치
    ↓
rad

PID 내부 오차
    ↓
rad

측정 모터 속도
    ↓
rad/s

최종 속도 명령
    ↓
°/s
```

## 18.3 PID 게인과 시간 파라미터

직접 게인 방식:

```text
Kp = 비례 게인
Ki = 적분 게인
Kd = 미분 게인
```

시간 파라미터 방식:

```text
Kp = 비례 게인
Ti = 적분 시간
Td = 미분 시간
```

변환:

```text
Ki = Kp / Ti
Kd = Kp × Td
```

## 18.4 지글러–니콜스

```text
Ki = 0
Kd = 0
   ↓
Kp 증가
   ↓
지속적인 진동
   ↓
Ku 측정
   ↓
Tu 측정
   ↓
Ziegler–Nichols 공식
   ↓
Kp / Ti / Td 계산
   ↓
필요하면 Ki / Kd로 변환
   ↓
실제 로봇에서 미세 조정
```

## 18.5 PID를 실제 관절의 움직임으로 이해하기

```text
목표 = 45°

현재 = 5°

       ↓

error = +40°

       ↓

Kp
"아직 40°나 남았으니 강하게 움직이자."

       ↓

관절 빠르게 이동

       ↓

현재 = 43°

error = +2°

       ↓

Kp 출력 감소

       ↓

관절이 목표에 접근

       ↓

너무 빠르게 접근하면

       ↓

Kd
"속도가 너무 빠르니 제동하자."

       ↓

목표 근처에서 감속

       ↓

현재 = 43°
error = +2°가 계속 남는다면

       ↓

Ki
"2° 오차가 계속 발생하고 있다."

       ↓

오차 누적

       ↓

추가 출력

       ↓

43° → 44° → 45°

       ↓

error ≈ 0°
```

따라서 PID는:

> **Kp로 빠르게 접근하고, Kd로 과도한 움직임을 억제하며, Ki로 마지막까지 남는 오차를 보정하는 제어 방식이다.**

# 19. 오늘의 필수 이해 기준

이번 강의에서는 PID 계산식을 전부 암기하는 것보다 **제어기가 실제 시스템에서 왜 그렇게 움직이는지를 설명할 수 있는 것**이 중요하다.

아래 세 가지를 이해하면 오늘 실습의 최소 준비가 된 것이다.

---

## 필수 ① 안정 · 한계 안정 · 불안정

시스템의 응답을 그래프로 보면 크게 다음 세 가지 상태로 구분할 수 있다.

### 안정

시간이 지나면서 출력이 목표값에 가까워지고 진동도 점점 줄어든다.

```text
목표
────────────────────────

       /\
      /  \__
_____/      \____
```

### 한계 안정

진동이 계속되지만 진동의 크기가 줄어들지도 커지지도 않는다.

```text
목표
────────────────────────

    /\    /\    /\    /\
___/  \__/  \__/  \__/  \__
```

이 상태가 지글러–니콜스에서 `Ku`를 찾을 때 사용하는 중요한 상태이다.

### 불안정

시간이 지날수록 진동이 커지거나 출력이 발산한다.

```text
목표
────────────────────────

   /\       /\          /\
  /  \     /  \        /  \
_/    \___/    \______/    \____
```

---

## 필수 ② "모든 극점이 s-평면 왼쪽에 있으면 안정"

제어 시스템의 안정성을 판단할 때 시스템의 **극점(pole)** 위치를 이용할 수 있다.

기본적인 판별 규칙은:

```text
모든 극점이 s-평면의 왼쪽
        ↓
      안정
```

반대로:

```text
오른쪽에 극점 존재
        ↓
      불안정
```

경계에 해당하는 경우에는 한계 안정과 관련된 상태가 나타날 수 있다.

이번 단계에서는 복잡한 극점 계산 자체보다:

> **"극점의 위치를 통해 시스템이 안정한지 불안정한지 판단할 수 있다."**

라는 관계를 이해하는 것이 중요하다.

---

## 필수 ③ 이득을 키우면 왜 발산하는가?

이 부분은 지연의 관점에서 이해하면 쉽다.

실제 로봇 관절은 명령을 내리자마자 정확히 그 위치에 도착하지 않는다.

예를 들어:

```text
목표 = 90°
현재 = 80°
```

라서 모터에 강한 출력을 줬다고 하자.

그런데 모터와 감속기에는 물리적인 관성, 마찰, 지연이 존재한다.

따라서 명령을 받은 순간 바로:

```text
80° → 90°
```

으로 가지 않는다.

실제로는:

```text
80°
 ↓
85°
 ↓
90°
 ↓
95°
```

처럼 목표를 지나칠 수 있다.

이때 Kp가 너무 크면:

```text
목표보다 멀리 있음
      ↓
큰 출력
      ↓
관절 이동
      ↓
목표를 지나침
      ↓
반대 방향의 큰 오차
      ↓
큰 반대 출력
      ↓
다시 목표를 지나침
```

이라는 과정이 반복된다.

결국:

```text
작은 Kp
→ 안정적으로 수렴

큰 Kp
→ 오버슈트 증가

더 큰 Kp
→ 지속적인 진동

더 큰 Kp
→ 진동이 점점 커짐
→ 불안정 / 발산
```

이 될 수 있다.

### 지연이 핵심인 이유

제어기는 **현재 측정값을 보고 판단하지만, 모터의 움직임은 즉시 끝나지 않는다.**

따라서 제어기가:

```text
"아직 목표에 못 갔네!"
```

라고 판단해서 계속 강한 출력을 보내는 동안 실제 관절은 이미 목표를 향해 계속 움직이고 있을 수 있다.

이것이 큰 이득에서 오버슈트와 진동이 커지는 중요한 이유 중 하나이다.

---

## 심화 — 여유가 된다면

오늘 반드시 필요한 내용은 아니지만 다음 개념까지 연결할 수 있다.

- 극점과 정착시간의 관계
- 특성방정식 `1 + KpG(s) = 0`
- Ziegler–Nichols 계수표의 의미
- 미분 필터와 측정값의 노이즈
- Anti-windup과 적분항 포화 문제

이 부분은 **위치와 운명의 대응**을 이해하는 정도로 넘어가도 된다.

---

# 오늘의 핵심 한 문장

> **PID는 목표와 현재 상태의 오차를 이용해 모터를 계속 보정하는 제어 방식이며, Kp는 현재 오차에 반응하고, Ki는 지속되는 오차를 보정하고, Kd는 빠른 움직임을 제동한다. Kp를 지나치게 키우면 시스템의 지연과 관성 때문에 오버슈트와 진동이 커지고 결국 불안정해질 수 있다.**

```text
목표
 ↓
오차
 ↓
PID
 ↓
모터 출력
 ↓
관절 움직임
 ↓
현재 상태
 ↓
다시 오차 계산
 ↺
```

이 폐루프의 흐름을 실제 `position_deg`, `error_deg`, `u_deg_s` 그래프와 연결해서 설명할 수 있으면 이번 PID 실습의 핵심을 이해한 것이다.
