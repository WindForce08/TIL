## 1. Keep — 잘했고 계속할 것

**K1. 시험을 먼저 만들고 고쳤다**
- 펌웨어 v5 는 시험부터 만들어 v4 에서 17개 중 14개가 실패하는 것을 보고 구현함 (10-26). 그리퍼 막힘 보호는 보호 코드를 빼면 시험이 실패하는 것까지 확인함 (10-27).
- SIL 시험이 65개 (10-26) → 130개 (11-11) 로 늘었고, PR 은 "실패 0" 을 확인하고 올림.

**K2. 실물은 작게, 하나씩 시험했다**
- 팔 모터를 한 대씩 붙이고 ≤ 0.1 rad 이동부터 시작해 J2 EEPROM 한계 · J1 180° 어긋남을 사고 없이 찾음 (10-26, 11-09).
- 바퀴는 띄운 채 최고 속도 → 바닥 직진 → 회전 순서로 넓혀 감 (11-11).

**K3. 감이 아니라 숫자로 판단했다**
- footprint 는 Gazebo 미션 비교 (볼록 6각형 2/2 vs 직사각형 1/2), Nav2 튜닝은 12 목표 12/12, 경로 품질은 기준 주행 기록 (제자리 회전 37번 · 2717°) 으로 정함 (11-10, 11-12).
- PPO 경로의 후진 비율 74 % 를 재서 주행 규칙 v2 의 근거로 씀 (11-14).

**K4. 원인을 끝까지 찾았다**
- AMCL 위치 잃음 = SLAM 지도 어긋남 (11-04), Nav2 가 되돌아감 = 기본 BT 의 지난 점 처리 (11-13), 리모컨 무반응 = UART2 (11-13), 위치 추정 실패 = 라이다 두 대 180° (11-14).

**K5. 막혔을 때 빨리 방향을 바꿨다**
- 시간이 부족하자 차체 재설계를 멈추고 (10-26), 차체가 폐기되자 팔만 먼저 진행함 (10-27).
- PPO 정책을 실물에 못 쓰는 것을 확인하고 대회 전날 계획기 + Nav2 따라가기로 시연 방식을 바꿈 (11-15).

**K6. 결정과 위험한 작업은 내가 직접 했다**
- git · 펌웨어 업로드 · 모터 구동 · 조립은 직접 하고, AI 에게는 "git 금지 · 승인 뒤 수정" 경계를 줌 (10-27 이후). 문제가 생기면 바로 규칙으로 만듦.
- 원본은 두고 사본 · scratchpad 에서 먼저 시험한 뒤 옮김 (10-27, 10-28, 11-01).

**K7. 기록하고 넘겨줄 수 있게 남겼다**
- 매일 업무일지 · TODO · `CLAUDE.md` 진행 메모, 팀원이 혼자 주행 시험을 할 수 있는 안내 문서 · 페이지 (PR #306, 11-15).
- 쌓인 이슈 10개를 닫고 모음 이슈로 정리, 댓글은 표 · 목록으로 읽기 쉽게 씀 (11-10).

## 2. Problem — 힘들었던 점 · 아쉬운 점

### 2.1 힘들었던 부분

**P1. 처음 2주를 쓴 차체가 폐기됐다**
- 10-15 부터 4륜 → 6WD 차체 · URDF · 웹 시뮬레이터 · 보관함 계획에 시간을 많이 썼는데, 10-26 시간 부족으로 재설계를 멈추고 10-27 1안이 "프린터가 못 뽑아" 폐기됨.
- 팀원 2안으로 바뀌면서 그동안 만든 Isaac 폴더 · 공유 URDF 는 참고용으로만 남음.

**P2. 실물 문제가 대회 직전에 몰려 나왔다**
- 바닥 주행은 11-11, 실제 미로 주행은 11-13, 실물 시연은 11-14 에 처음 함 (대회 11-16).
- 그사이 벨트 빠짐 (11-11 · 11-13), 켜는 순서 FAULT · USB 끊김 (11-11 · 11-13), 라이다 두 대 180° (11-14), 마지막 날 벨트 v7 로 바퀴 힘 감소 (11-15) 가 연달아 나옴.
- Gazebo 미션 DONE 도 팔 · 인지 · 잠금은 mock 이었음 (11-09). 시뮬에서 되는 것과 실물에서 되는 것의 차이가 컸음.

**P3. 밤새 학습한 PPO 정책을 실물에 못 썼다**
- 11-02 부터 여러 번 밤샘 학습을 돌렸지만, 마지막 날 결론은 "오늘 실물에 못 씀" — 학습 덜 됨 · 벨트 바뀜 · 실물용 ROS 노드 없음 · 무작위화 안 함 · 경로 하나만 배움 (11-15).

**P4. 팀 dev 가 빨리 바뀌어 맞추는 데 힘이 많이 들었다**
- 작업 폴더에서 팔 작업이 빠져 다시 이식 (10-27), stash · autostash 충돌 정리 (11-03, 11-04), PR #115 · #117 이 1분 차이로 병합돼 localization 두 벌 (11-06).
- 팀원과 같은 일을 겹쳐 함 (11-06), 리뷰하려던 PR 이 먼저 병합됨 (11-10).

**P5. 지도와 실제 경기장이 달랐다**
- SLAM 지도 동쪽 8 ~ 15 cm 어긋남 (11-04 · 11-09), box1 이 지도보다 북쪽 18.6 cm (11-14), L3 정지점이 상자 면에서 3.4 cm (11-15). 실측은 대회 이틀 전 밤에야 함.

**P6. AI 결과를 확인하는 데 에너지가 많이 들었다**
- 확인 없이 원하지 않은 학습을 돌림 (11-02), git 작업에 다른 팀 파일이 섞임 (10-27), 틀린 명령 · 경로 · 포트 안내 (11-09 · 11-11 · 11-13), 실행 중 스크립트를 고쳐 로그가 날아감 (11-13), 바퀴 간격을 잘못 설명 (10-29).

**P7. 장비 · 시간 · 체력**
- apt 고장 (10-15), GPU 멈춤 · 재부팅 (10-26), 세션 사용 한도 (10-26 · 11-09), 노트북 디스크 100 % (11-15).
- 새벽 작업 (10-26, 11-01) 과 마지막 주 밤 11시 전후까지 작업 (11-13 ~ 11-15).

### 2.2 했어야 했다고 생각한 부분

**P8. 주행 규칙을 처음부터 숫자로 정했어야 했다**
- "제자리 회전 규칙이 불명확했다. 180° · 360° 회전을 금지하고 회전 범위를 제한했어야 했다" (11-14 내 지적). 규칙 없이 학습해 후진 74 % 가 나왔고, Nav2 제자리 회전에서 벨트가 빠짐.

**P9. 실물 통합을 더 일찍 했어야 했다**
- 차체를 다듬기 전에 최소 차체로 바닥 주행 · 회전 · 벨트 한계를 먼저 쟀다면 회전 금지 · 벨트 문제를 1 ~ 2주 일찍 알았을 것.

**P10. 설계 전에 출력 가능성과 팀 합의를 먼저 확인했어야 했다**
- 프린터 크기 · 출력 시간 · 공차 (공차 시험편을 빼기로 한 결정, 10-20) 를 먼저 보고, 팀이 쓸 차체를 합의한 뒤 상세 설계를 했어야 함.

**P11. 학습 전에 목표 · 보상 · 확인 방법을 먼저 정했어야 했다**
- "원한 건 보상을 정하고 웨이포인트를 하나씩 늘려 최종 목표까지, 내가 확인할 수 있게" (11-02 내 지적). 실물에 올릴 경로 (ROS 노드 · 무작위화) 도 학습보다 먼저 만들었어야 함.

**P12. 경기장 실측을 첫 실물 주행 전에 했어야 했다**
- 상자 · L 자리를 미리 쟀다면 box1 앞 멈춤 (11-14) 과 정지점 수정 (11-15) 을 줄였을 것.

**P13. 이슈를 시작하기 전에 팀원 댓글 · PR 을 먼저 확인했어야 했다**
- 같은 일을 겹쳐 함 (11-06), 아침에 쓴 #114 초안을 다시 확인하지 않고 올려 앞선 댓글과 어긋남 (11-09).

**P14. 실물 조건 그대로 확인했어야 했다**
- DRIVE 자세를 짐칸이 빈 상태로 확인해 퍽과 10.6 mm 겹치는 것을 놓침 (11-10). 켜는 순서 (배터리 → USB) 도 점검표로 만들었어야 함.

**P15. 실물 시험 기록을 먼저 확보했어야 했다**
- S6 에서 정면이 벽에 닿았을 때 궤적 기록이 없어 원인을 못 밝힘 (11-15, Ctrl+C 에 tee 가 죽음).

## 3. Try — 다음에 해 볼 것

**T1. D-day 역산 일정과 실물 마일스톤** (← P2 · P9)
- 첫 주 안에 "최소 차체가 바닥에서 움직임", 대회 1주 전에는 기능 동결 · 실물 반복만.

**T2. 요구사항 · 제약을 숫자 표로 먼저** (← P8 · P11)
- 회전 · 후진 · 속도 · 정지 거리 같은 규칙을 시작할 때 팀과 정하고, 학습 · 튜닝 · 평가가 같은 표를 쓰게 함.

**T3. 상세 설계 전 설계 리뷰 체크리스트** (← P1 · P10)
- 출력 가능 (프린터 크기 · 시간) · 공차 시험편 · 조립 · 배선을 확인하고 팀 합의를 받은 뒤 상세 설계.

**T4. Sim-to-Real 을 처음부터 계획에 넣기** (← P3 · P11)
- 실물 측정값 (마찰 · 벨트 · 지연) 으로 시뮬을 맞추고, 무작위화 · 실물 추론 노드를 학습보다 먼저 만듦. RL 은 "실물에 올릴 수 있나" 를 기준으로 계속할지 정함.

**T5. 경기장 · 장비 실측을 첫날에** (← P5 · P12)
- 지도와 실물 차이를 표로 남기고, 실측판 지도로 시뮬함.

**T6. 팀 협업 습관** (← P4 · P13)
- 이슈 시작 전 기존 댓글 확인 + "내가 함" 댓글, 작은 PR 자주, dev 는 매일 아침 받기, 리뷰 요청은 PR 올릴 때 바로.

**T7. AI 사용 규칙을 첫날 `CLAUDE.md` 에** (← P6)
- git · 장치 쓰기 · 설치는 직접, 실행 전 계획 확인, 한글 보고, 초안은 올리기 직전 재확인, 실행 중인 스크립트는 고치지 않기.

**T8. 실물 점검표와 기록 먼저** (← P14 · P15)
- 켜는 순서, 저장 확인 (Ctrl+S), 실물 상태 (짐칸 채움 등), 주행 기록이 바로 디스크에 쓰이는지 시험 전에 확인.

**T9. 체력 관리** (← P7)
- 밤에는 학습 · 시뮬 묶음만 걸어 두고 쉼. 대회 전날은 새 기능보다 점검 · 리허설.

## 4. KPT 요약

- **Keep**: 시험을 먼저 만들고, 실물은 작게 하나씩, 판단은 숫자로 했다. 막히면 빨리 방향을 바꾸고 위험한 작업은 직접 하며, 기록을 남겨 팀이 이어받을 수 있게 했다.
- **Problem**: 처음 2주 동안 만든 차체가 폐기됐고, 실물 문제 (벨트 · 라이다 · 지도 차이) 가 대회 직전에 몰렸으며, 밤샘 학습한 PPO 는 실물에 못 썼다. 주행 규칙을 숫자로 먼저 정하고 실물 · 경기장을 더 일찍 확인했어야 했다.
- **Try**: 요구사항 · 제약을 숫자 표로 먼저 정하고, 첫 주에 최소 차체를 바닥에서 움직인다. 팀 · AI 작업 규칙과 실물 점검표를 첫날 만들어 둔다.

**한 줄 정리**
- 설계 · 시뮬레이션 · 펌웨어 · 주행까지 넓게 맡아 시뮬에서는 대부분 해냈지만, 실물을 늦게 만난 것이 가장 아쉬움. 다음에는 **규칙을 숫자로 먼저 정하고, 실물을 첫 주에 움직인다.**
