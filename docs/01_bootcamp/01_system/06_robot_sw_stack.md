# 로봇 SW 스택: 인지-판단-제어 계층의 역할과 멀티레이트 데이터 흐름

## 핵심 요점

- **계층별 역할이 명확해요**: 인지(센서 데이터 처리) → 판단(경로 계획) → 제어(모터 조작)로 순차적으로 움직여요.
- **갱신 주기가 다르다는 게 핵심이에요**: 제어 계층(100Hz~10kHz) > 인지 계층(~30fps) > 판단 계층(가장 느림) 순서로 빠르게 동작해요.
- **멀티레이트 데이터 흐름이란 각 계층이 서로 다른 속도로 정보를 주고받는 것**을 의미해요.

## 각 계층의 역할 정리

**인지 계층**은 카메라, 라이다 같은 센서에서 들어오는 데이터를 처리해서 장애물의 위치나 로봇의 현재 상태를 추정하는 역할을 맡아요. 센서의 프레임률(예: 초당 30프레임)에 맞춰 갱신되기 때문에 중간 정도의 속도로 동작합니다.

**판단 계층**은 인지 계층에서 얻은 정보를 바탕으로 경로를 계획하고 다음 동작을 결정해요. 환경이나 목표 변화에 따라 필요할 때만 갱신되므로 가장 느린 속도로 동작합니다.

**제어 계층**은 판단 계층의 지시와 현재 상태의 오차를 계산해서 모터를 조작하고 구동해요. 모터와 기구의 동역학을 다루기 때문에 가장 빠르고 정밀하게(100Hz~10kHz 수준) 작동합니다.

## 멀티레이트 데이터 흐름의 의미

각 계층이 서로 다른 갱신 주기를 가지고 있다는 것은, 로봇이 상황의 변화에 빠르게 대응하면서도 불필요한 계산을 줄이는 방식으로 설계되었다는 뜻이에요. 제어 계층이 빠르게 움직일 수 있어야 모터를 정밀하게 제어할 수 있고, 판단 계층이 느려도 경로 계획의 정확성에는 큰 영향을 주지 않는 거죠.

## 헷갈리기 쉬운 지점

**각 계층의 역할을 섞어 생각하지 않도록 주의해요**: 경로 계획은 반드시 판단 계층, 센서 해석은 반드시 인지 계층, 모터 오차 제어는 반드시 제어 계층의 몫이에요.

## 이번에 헷갈렸던 부분 다시 짚기

혹시 "인지 계층도 센서와 모터를 다루지 않나?" 하고 생각했다면, 인지 계층은 **센서 데이터를 읽고 해석하는 것**만 담당한다고 정확히 기억하세요. 모터를 실제로 움직이는 명령을 내리는 건 제어 계층의 역할이에요. 마찬가지로 "경로를 계획하는 건 판단 계층이라고 했는데, 인지 계층이 현재 상태를 알아야 계획할 수 있지 않나?" 생각이 들 수 있어요. 맞습니다. 인지 계층에서 처리한 정보가 판단 계층으로 흘러가므로, 두 계층은 연결되어 있지만 **역할은 엄격하게 분리**되어 있다고 이해하면 돼요.

# 실시간성: 주기, 지연, 지터와 Hard/Firm/Soft 실시간

## 핵심 요점

- **주기, 지연, 지터는 서로 독립적인 개념**이에요. 주기가 짧다고 해서 지터가 작은 건 아니고, 평균 지연이 짧아도 변동이 크면 제어 시스템에 문제가 생깁니다.
- **실시간성의 본질은 '마감 준수'**예요. 정해진 시간 안에 작업을 마칠 수 있는지가 핵심입니다.
- **Hard/Firm/Soft는 마감 위반의 결과로 구분**돼요. 얼마나 위험한가에 따라 분류합니다.

---

## 주기, 지연, 지터 이해하기

**주기(Period)**는 같은 작업이 반복되는 시간 간격이에요. 예를 들어 100ms마다 센서를 읽는 루프의 주기는 100ms입니다.

**지연(Latency)**은 입력 신호가 들어온 순간부터 출력이 나갈 때까지 걸리는 시간이에요. 센서 신호가 들어온 후 제어 명령이 액추에이터에 도달하는 데 걸리는 시간이라고 보면 됩니다.

**지터(Jitter)**는 주기가 일정하지 않은 정도를 나타내요. 100ms마다 실행하려던 작업이 어떨 때는 95ms에, 어떨 때는 110ms에 실행되는 식의 변동입니다.

---

## 지터가 위험한 이유

제어 시스템(예: PID 제어)은 일정한 주기(Δt)를 기본 가정으로 설계돼요. 적분과 미분을 계산할 때 이 Δt 값을 사용하니까요.

지터가 크면 실제 주기가 예상과 달라져서 적분/미분 계산이 틀어지고, 오차가 계속 누적됩니다. 결과적으로 시스템이 진동하거나 발산해버릴 수 있어요.

이를 해결하려면 **RTOS(실시간 운영체제)나 리눅스 실시간 패치**를 사용해 OS 스케줄러와 인터럽트를 정확하게 관리하고, 중요한 작업의 우선순위를 높여야 합니다.

---

## Hard/Firm/Soft 실시간 구분하기

실시간 시스템을 분류할 때 가장 중요한 기준은 '**마감을 놓쳤을 때 무슨 일이 일어나느냐**'예요.

**Hard 실시간**: 마감을 어기면 **시스템이 완전히 망가지거나 위험 상황**이 발생합니다. 예를 들어 항공기 자동 조종, 의료 기기, 원전 제어처럼 사람의 생명이나 재산에 직결된 경우예요. 마감 준수가 절대적입니다.

**Firm 실시간**: 마감을 어긴 결과값은 **쓸모없어져서 버려져요**. 하지만 시스템 자체는 계속 돌아갑니다. 예를 들어 영상 스트리밍에서 한두 프레임을 놓쳐도 재생은 계속되는 경우입니다.

**Soft 실시간**: 마감을 어겨도 **결과값을 계속 사용할 수 있지만 가치가 떨어져요**. 응답성이 좀 떨어지는 정도예요. 일반적인 GUI 애플리케이션이나 멀티미디어 플레이어가 해당합니다.

---

## 로봇 작업의 실시간 분류

로봇의 작업이 어디에 속하는지는 **그 작업이 실패했을 때 미치는 영향**으로 결정돼요.

로봇이 정밀한 물건을 집거나 사람 근처에서 동작할 때처럼 안전이 중요하면 **Hard 실시간**이에요. 반대로 정해진 루트를 따라가는 일이거나, 약간의 지연이 문제 없으면 **Soft 실시간** 정도일 수 있습니다.
