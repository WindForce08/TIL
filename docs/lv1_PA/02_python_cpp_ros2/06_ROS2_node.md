# Physical AI 연산 분담: 임베디드 · Edge AI · 클라우드

## 1. 학습 목표

> **"임베디드, Edge AI, 클라우드의 연산 분담을 설명하고 지연 예산과 데이터 전송량을 근거로 어떤 작업을 어디서 처리할지 판단할 수 있다."**

### 핵심 키워드

- Physical AI
- 임베디드 (Embedded)
- Edge AI
- 클라우드 (Cloud)
- 지연 예산 (Latency Budget)
- 데이터 전송량 (Data Volume)
- 연산량 (Computational Load)

---

# 2. Physical AI란?

**Physical AI는 현실 세계의 환경과 상황을 인지하고, 센서 등으로 얻은 데이터를 바탕으로 판단하여 실제 행동까지 수행하는 AI이다.**

기본적인 흐름:

```text
현실 세계
   ↓
센서로 데이터 수집
   ↓
인지 / 인식
   ↓
판단
   ↓
행동 결정
   ↓
모터·액추에이터 등을 통한 실제 행동
```

Physical AI는 현실 세계와 직접 상호작용하기 때문에 단순히 높은 연산 성능만 필요한 것이 아니라 **실시간성, 네트워크 지연, 데이터 전송량, 안정적인 제어** 등을 함께 고려해야 한다.

---

# 3. 왜 연산을 분담하는가?

Physical AI에서는 동시에 다양한 작업이 발생한다.

예를 들어 로봇이라면:

- 센서 데이터 수집
- 장애물 감지
- 객체 인식
- 센서 융합
- 경로 계획
- 모터 제어
- AI 추론
- 모델 학습
- 데이터 분석

이 모든 작업을 하나의 장치에서 처리할 수도 있지만, 작업마다 요구사항이 다르기 때문에 **임베디드 · Edge AI · 클라우드로 적절하게 연산을 분담하는 것이 효율적**이다.

---

# 4. 임베디드 · Edge AI · 클라우드

## 4.1 임베디드

Physical AI 장치 자체에 탑재된 컴퓨팅 환경이다.

### 특징

- 장치와 매우 가까움
- 네트워크 연결 없이도 처리 가능
- 매우 빠른 반응이 필요한 작업에 적합
- 연산 자원이 상대적으로 제한적

### 대표적인 작업

- 모터 제어
- 센서의 기본적인 데이터 처리
- 긴급 정지
- 안전 관련 제어
- 매우 짧은 지연이 필요한 작업

## 4.2 Edge AI

센서와 장치에 가까운 네트워크 환경에서 AI 연산을 수행한다.

### 특징

- 클라우드보다 장치와 가까움
- 네트워크 지연을 줄일 수 있음
- 임베디드보다 높은 연산 능력을 활용할 수 있음
- 대용량 센서 데이터를 가까운 곳에서 처리하기 좋음

### 대표적인 작업

- 객체 인식
- 영상 분석
- 센서 융합
- AI 추론
- 주변 환경 분석

## 4.3 클라우드

원격 서버의 높은 연산 능력을 활용하는 방식이다.

### 특징

- 매우 높은 연산 능력 활용 가능
- 대규모 데이터 처리에 적합
- 모델 학습 및 대규모 분석에 유리
- 네트워크를 통한 데이터 전송이 필요함
- 네트워크 상태에 따라 지연이 발생할 수 있음

### 대표적인 작업

- AI 모델 학습
- 대규모 데이터 분석
- 장기간의 데이터 저장
- 복잡하고 무거운 연산
- 실시간성이 낮은 작업

---

# 5. 가장 중요한 두 가지 판단 기준

연산 위치를 결정할 때 특히 중요한 것이 **지연 예산**과 **데이터 전송량**이다.

처음 설명할 때 다음 표현에서 혼동이 있었다.

> ❌ "데이터 전송량에 따른 지연 예산"

이렇게 표현하면 **데이터 전송량이 지연 예산을 결정한다**는 의미처럼 들릴 수 있다.

실제로는 두 가지가 **서로 다른 판단 기준**이다.

---

# 6. 지연 예산 (Latency Budget)

지연 예산은 쉽게 말하면:

> **"이 작업은 최대 얼마의 시간 안에 끝나야 하는가?"**

라는 시간상의 제약이다.

예:

```text
안전 정지
↓
매우 빠른 반응 필요
↓
매우 작은 지연 예산
```

반면:

```text
AI 모델 학습
↓
즉각적인 반응 필요 없음
↓
상대적으로 큰 지연 허용
```

### 핵심

```text
지연 예산
= 작업이 완료되어야 하는 최대 허용 시간
```

---

# 7. 데이터 전송량 (Data Volume)

데이터 전송량은:

> **"이 작업을 위해 네트워크를 통해 얼마나 많은 데이터를 이동해야 하는가?"**

를 의미한다.

예를 들어 카메라는 계속해서 많은 양의 영상 데이터를 생성한다.

```text
카메라
   ↓
고해상도 영상
   ↓
대용량 데이터
   ↓
네트워크 전송
```

이 데이터를 전부 클라우드로 전송하면:

- 높은 네트워크 대역폭이 필요하고
- 전송 시간이 증가할 수 있으며
- 네트워크 상태에 따라 지연이 발생할 수 있다.

따라서 카메라와 가까운 Edge에서 먼저 처리하는 방법이 효과적이다.

```text
카메라
   ↓
Edge AI
   ↓
객체 인식
   ↓
"사람 2명 발견"
   ↓
필요한 결과만 전송
```

즉, 원본 데이터를 그대로 보내는 대신 **필요한 정보로 가공한 뒤 전송량을 줄일 수 있다.**

---

# 8. 지연 예산과 데이터 전송량의 차이

| 구분 | 지연 예산 | 데이터 전송량 |
|---|---|---|
| 핵심 질문 | 얼마나 빨리 끝내야 하는가? | 얼마나 많은 데이터를 옮겨야 하는가? |
| 본질 | 시간 제약 | 통신량 |
| 단위 예시 | ms, s | MB, GB, MB/s 등 |
| 결정 요소 | 작업의 실시간성 | 데이터의 크기와 전송 빈도 |
| 역할 | 처리 위치 결정 | 처리 위치 결정 |

### 핵심

```text
지연 예산 ≠ 데이터 전송량
```

둘은 서로 다른 개념이다.

하지만 실제 시스템에서는 데이터 전송량이 많아지면 네트워크 전송 시간이 증가하여 **전체 시스템의 실제 지연에 영향을 줄 수 있다.**

따라서:

```text
데이터 전송량 증가
       ↓
네트워크 부담 증가
       ↓
전송 시간 증가 가능
       ↓
전체 처리 지연 증가 가능
```

이라고 이해하면 된다.

---

# 9. 연산량도 함께 고려해야 한다

지연 예산과 데이터 전송량만 보는 것도 충분하지 않다.

작업 자체가 얼마나 무거운 연산을 요구하는지도 중요하다.

예:

- 간단한 모터 제어 → 낮은 연산량
- 객체 탐지 → 높은 연산량
- 대규모 AI 모델 학습 → 매우 높은 연산량

따라서 실제로는 다음 세 가지를 함께 고려한다.

```text
지연 예산
    +
데이터 전송량
    +
연산량
    ↓
어디에서 처리할 것인가?
```

---

# 10. 작업 배치의 기본적인 판단

| 판단 기준 | 임베디드 | Edge AI | 클라우드 |
|---|---|---|---|
| 지연 요구 | 매우 엄격 | 비교적 엄격 | 상대적으로 여유 |
| 네트워크 의존성 | 거의 없음 | 낮음 | 높음 |
| 연산 능력 | 제한적 | 중간~높음 | 매우 높음 |
| 데이터 처리 | 센서·제어 중심 | 실시간 AI 추론 | 대규모 데이터 처리 |
| 대표 작업 | 모터 제어, 긴급 정지 | 객체 인식, 영상 분석 | 학습, 대규모 분석 |

> ※ 실제 시스템에서는 하드웨어 구성과 작업 요구사항에 따라 달라질 수 있다.

---

# 11. 예시 ① 카메라 영상 처리

## 클라우드에서 전체 영상 처리

```text
카메라
   ↓
대용량 영상 전송
   ↓
클라우드
   ↓
AI 추론
   ↓
결과 반환
```

### 문제점

- 대역폭 부담
- 네트워크 전송 지연
- 네트워크 상태에 따른 불확실성
- 실시간성이 중요한 경우 불리할 수 있음

## Edge AI에서 처리

```text
카메라
   ↓
Edge AI
   ↓
객체 인식
   ↓
"사람 발견"
"차량 발견"
"장애물 발견"
   ↓
필요한 정보만 전송
```

### 장점

- 원본 영상 전송량 감소
- 네트워크 의존성 감소
- 빠른 AI 추론 가능
- 실시간 환경 인식에 유리

# 12. 예시 ② 안전 정지

로봇이 주행 중 장애물을 발견했다고 가정한다.

```text
장애물 감지
     ↓
즉시 판단
     ↓
모터 정지
```

이 작업에서는 데이터가 얼마나 큰가보다:

> **"얼마나 빨리 정지해야 하는가?"**

가 훨씬 중요하다.

따라서 네트워크를 거쳐 원격 클라우드에서 판단하기보다는 **장치 가까이에서 처리하는 것이 유리하다.**

---

# 13. 처음 설명에서 수정할 부분

처음 설명:

> "데이터 전송량에 따른 지연 예산을 고려해..."

### 수정

> **"지연 예산과 데이터 전송량을 함께 고려해..."**

또는 더 정확하게:

> **"작업의 지연 요구사항, 데이터 전송량, 연산량 등을 고려하여 적절한 연산 위치를 결정한다."**

이렇게 표현하는 것이 좋다.

---

# 14. 최종 설명

> **Physical AI에서는 현실 세계의 센서 데이터를 바탕으로 인식·판단·행동을 수행하기 때문에 작업의 특성에 따라 연산을 임베디드, Edge AI, 클라우드로 분담할 필요가 있다. 이때 연산 위치를 결정할 때는 지연 예산, 데이터 전송량, 연산량 등을 함께 고려해야 한다. 지연 예산은 작업이 얼마나 빠르게 완료되어야 하는지를 나타내고, 데이터 전송량은 네트워크를 통해 얼마나 많은 데이터를 이동해야 하는지를 나타낸다. 따라서 매우 빠른 반응이 필요한 제어 작업은 임베디드에서, 대용량 센서 데이터를 빠르게 처리해야 하는 AI 추론은 Edge에서, 상대적으로 지연에 여유가 있고 높은 연산 능력이 필요한 작업은 클라우드에서 처리하는 방식으로 분담할 수 있다.**

---

# 15. 핵심 한 문장

> **"어디서 처리할지는 얼마나 빨라야 하는지(지연 예산), 얼마나 많이 보내야 하는지(데이터 전송량), 얼마나 무거운 연산인지(연산량)를 보고 결정한다."**

---

# 16. 최종 암기 구조

```text
                    Physical AI
                         │
           현실 세계를 인지하고 판단하여 행동
                         │
                    연산 분담 필요
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
     임베디드          Edge AI          클라우드
        │                │                │
   빠른 제어         실시간 AI 추론      고성능 연산
   안전 정지         객체 인식          모델 학습
   센서 처리         영상 분석          대규모 분석
        │                │                │
        └────────────────┼────────────────┘
                         ↓
                 작업 특성에 따라 결정
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
       지연 예산       데이터 전송량      연산량
          │              │              │
      "얼마나 빨리?"  "얼마나 많이?"   "얼마나 무거워?"
```

### 가장 중요한 교정 포인트

```text
❌ 데이터 전송량 → 지연 예산

⭕ 지연 예산 + 데이터 전송량 + 연산량
                    ↓
              연산 위치 결정
```
