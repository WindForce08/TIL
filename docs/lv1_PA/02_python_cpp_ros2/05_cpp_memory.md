# 2. 스택(Stack)과 힙(Heap)

## 스택

스택은 함수나 스코프 안에서 사용하는 지역 변수와 객체를 자동으로
관리하는 영역이다.

``` cpp
void control_loop()
{
    double target = 0.5;
    Motor m;
}
```

함수가 시작되면 지역 변수와 객체가 생성되고, 함수/스코프가 끝나면
자동으로 수명이 종료된다.

특히 객체의 경우 소멸자가 자동으로 호출된다.

``` text
control_loop() 실행
      ↓
지역 변수/객체 생성
      ↓
사용
      ↓
control_loop() 종료
      ↓
객체 소멸자 호출
      ↓
스택 공간 자동 정리
```

스택의 핵심은 단순히 "빠르다"가 아니라 **수명이 함수/스코프와 밀접하게
연결되어 자동으로 관리된다는 것**이다.

## 힙

힙은 프로그램 실행 중 동적으로 메모리를 확보해서 사용하는 영역이다.

``` cpp
Motor* p = new Motor();
```

개념적으로:

``` text
Stack                         Heap

┌─────────────┐              ┌─────────────┐
│ p           │─────────────→│ Motor 객체  │
└─────────────┘              └─────────────┘
```

여기서 포인터 변수 `p`와 `p`가 가리키는 `Motor` 객체는 서로 다른 존재다.

힙을 사용하면 함수/스코프의 수명과 객체의 수명을 분리할 수 있다.

# 3. 참조(Reference)

참조는 기존 객체에 붙이는 또 하나의 이름이라고 이해할 수 있다.

``` cpp
int x = 10;
int& ref = x;
```

``` text
x
┌─────────┐
│   10    │
└─────────┘
    ↑
    │
   ref
```

``` cpp
ref = 20;
```

하면 `x`도 20이 된다.

## 함수에서 참조를 사용하는 이유

값으로 전달하면 데이터가 복사될 수 있다.

``` cpp
double process(std::vector<double> scan);
```

반면 참조를 사용하면 원본을 복사하지 않고 다룰 수 있다.

``` cpp
double process(const std::vector<double>& scan);
```

여기서:

-   `&` → 원본을 참조
-   `const` → 원본을 수정하지 않음

따라서 `const T&`는 큰 데이터를 불필요하게 복사하지 않고 읽기만 할 때
매우 유용하다.

------------------------------------------------------------------------

# 4. 포인터(Pointer)

포인터는 메모리 주소를 저장하는 변수다.

``` cpp
int x = 10;
int* p = &x;
```

각 부분의 의미:

``` text
&x
↓
x의 주소

p
↓
그 주소를 저장하는 포인터

*p
↓
p가 가리키는 대상의 실제 값
```

예:

``` cpp
*p = 30;
```

하면 `x`가 30이 된다.

## `&`와 `*`

``` cpp
int* p = &x;
```

-   `&x` → x의 주소
-   `int* p` → p는 int를 가리키는 포인터
-   `*p` → p가 가리키는 대상

------------------------------------------------------------------------

# 5. 참조와 포인터의 차이

                         참조 `&`             포인터 `*`
  ---------------------- -------------------- -------------------------
  기본 개념              기존 객체의 별명     주소를 저장하는 변수
  `nullptr`              불가능               가능
  다른 대상을 가리키기   일반적으로 불가능    가능
  사용법                 일반 변수처럼 사용   `*p`로 역참조
  대표적인 용도          함수 인자 전달       간접 접근, 동적 객체 등

참조의 역할이 복사 방지 하나로만 한정되는 것은 아니지만, 함수 인자에서
`const T&` 형태로 불필요한 복사를 막는 것이 매우 대표적인 사용법이다.

# 6. Raw Pointer의 문제

옛날 방식으로 힙 객체를 직접 관리할 수 있다.

``` cpp
Motor* p = new Motor();

// 사용

delete p;
```

하지만 개발자가 직접 수명을 관리해야 한다.

## 메모리 누수(Memory Leak)

``` cpp
Motor* p = new Motor();

// 사용

// delete를 깜빡함
```

객체는 힙에 남아 있지만 관리할 포인터를 잃을 수 있다.

``` text
Stack                 Heap

p ─────────────────→ Motor
                       ↑
                       │
                아무도 관리하지 않음
```

사용하지 않는 메모리가 계속 점유되는 것이 메모리 누수다.

## 댕글링 포인터(Dangling Pointer)

``` cpp
Motor* p = new Motor();

delete p;

p->setSpeed(0.5);  // 잘못된 사용
```

상황:

``` text
①
p ─────────→ Motor 객체

② delete p

p ─────────→ 삭제된 Motor

③ p->setSpeed()

삭제된 객체를 사용하려고 함
```

즉, **포인터는 여전히 주소를 가지고 있지만 그 주소에 있던 객체가 이미
삭제된 상태**를 댕글링 포인터라고 한다.

### 메모리 누수와 댕글링 포인터 비교

``` text
메모리 누수
→ 객체가 남아 있는데 관리할 포인터를 잃음

댕글링 포인터
→ 객체는 삭제됐는데 포인터가 여전히 그곳을 가리킴
```

# 7. RAII

RAII:

**Resource Acquisition Is Initialization**

핵심:

> 자원의 수명을 객체의 수명에 묶는다.

자원에는:

-   메모리
-   파일
-   소켓
-   mutex
-   기타 시스템 자원

등이 포함될 수 있다.

예:

``` cpp
{
    Motor m;

    // 사용
}
```

스코프가 끝나면 객체가 자동으로 소멸하고 자원도 정리된다.

``` text
Motor 생성
   ↓
사용
   ↓
스코프 종료
   ↓
소멸자 자동 호출
   ↓
자원 정리
```

RAII는 수동 자원 관리에서 발생하는 실수를 줄이는 C++의 핵심적인 설계
원칙이다.

# 8. 스마트 포인터

RAII를 힙 메모리 관리에 적용한 대표적인 도구가 스마트 포인터다.

대표적으로:

``` text
std::unique_ptr
std::shared_ptr
```

가 있다.

## unique_ptr --- 단독 소유

``` cpp
auto motor = std::make_unique<Motor>();
```

``` text
motor ─────────→ Motor
                   ↑
                소유자 1명
```

`unique_ptr`은 단독 소유권을 나타낸다.

스코프가 끝나면 자동으로 객체가 정리되므로 직접 `delete`할 필요가 없다.

복사할 수 없다.

``` cpp
auto b = motor;  // ❌
```

대신 이동할 수 있다.

``` cpp
auto b = std::move(motor);
```

이 경우 소유권이 `motor`에서 `b`로 이동한다.

## shared_ptr --- 공동 소유

``` cpp
auto lidar = std::make_shared<Lidar>();
```

여러 곳에서 하나의 객체를 공동 소유할 수 있다.

``` text
소유자 A ──┐
           ├──→ Lidar
소유자 B ──┘

참조 카운트 = 2
```

마지막 소유자가 사라져 참조 카운트가 0이 되면 객체가 자동으로 정리된다.

``` text
unique_ptr
→ 단독 소유

shared_ptr
→ 공동 소유
```

일반적으로 기본값은 `unique_ptr`로 생각하고, 정말 공유 소유권이 필요한
경우 `shared_ptr`을 사용하는 방향으로 이해한다.

# 9. ROS2와의 연결

ROS2 C++ 코드에서는 스마트 포인터가 자주 등장한다.

예:

``` cpp
auto msg = std::make_shared<MyMessage>();
```

ROS2에서 노드, 메시지 등의 객체를 다룰 때 스마트 포인터 기반의 수명
관리가 많이 사용된다.

따라서:

``` text
포인터
 ↓
RAII
 ↓
스마트 포인터
 ↓
객체 수명 관리
 ↓
ROS2 C++
```

로 연결된다.

# 10. 객체지향 / 다형성과의 연결

다음 단계에서는 상속과 다형성이 등장한다.

``` text
             Sensor
                │
       ┌────────┼────────┐
       ↓        ↓        ↓
     LiDAR    Camera     IMU
```

예:

``` cpp
class Sensor
{
public:
    virtual ~Sensor() = default;

    virtual std::vector<double> read() = 0;
};
```

그리고:

``` cpp
std::vector<std::unique_ptr<Sensor>> sensors;
```

처럼 여러 종류의 센서를 부모 타입인 `Sensor`로 관리할 수 있다.

여기서:

-   `virtual`
-   `override`
-   `virtual destructor`

등이 등장한다.

# 11. 템플릿

템플릿은 하나의 로직을 여러 타입에 사용할 수 있게 한다.

``` cpp
template <typename T>
T clamp(T value, T lo, T hi)
{
    return std::max(lo, std::min(value, hi));
}
```

예:

``` cpp
clamp(1.5, 0.0, 1.0);  // double
clamp(150, 0, 255);     // int
```

컴파일러가 사용된 타입에 맞는 코드를 생성한다.

# 12. STL

STL(Standard Template Library)은 검증된 자료구조와 알고리즘 모음이다.

  용도             Python    C++ STL
  ---------------- --------- -----------------------------------
  순서 있는 배열   `list`    `std::vector<T>`
  키-값 조회       `dict`    `std::map` / `std::unordered_map`
  중복 없는 모음   `set`     `std::set` / `std::unordered_set`
  고정 크기 묶음   `tuple`   `std::array`, `std::tuple`
  문자열           `str`     `std::string`

Physical AI/ROS2에서는 특히 `std::vector`를 매우 자주 사용한다.

예:

``` cpp
std::vector<double> scan = {0.3, 8.2, 0.5, 12.0};

scan.push_back(1.1);

double closest = *std::min_element(
    scan.begin(),
    scan.end()
);
```

# 14. 희우님의 최초 이해 내용 --- 원문 그대로

희우님이 작성한 문장을 토씨 하나 수정하지 않고 그대로 보존한다.

> C++에서는 메모리에 직접 접근하는것이 가능하다. 개발자가 직접 메모리에
> 생선된 객체에게 포인터를 지정해야한다. 메모리 효율을 위해서 필수적이지
> 않은 복사를 방지한다. 이것이 참조. 포인터는 말 그대로 주소처럼 변수를
> 가르키는것. 이 포인터는 개발자가 하나하나 지정/삭제 를 원활하게 하지
> 못하면 메모리에 쓰레기 데이터가 쌓이거나 불필요한 메모리 리소스를
> 사용하는 메모리 누수가 발생한다. 뎅글러 포인트는 잘 모르겠네. 이런
> 누수를 해결하기 위해서 RAII 가 나왔고 자원과 객체의 수명을
> 묶어버림으로써 자동적으로 메모리 리소스 관리가 가능하게 하였다. 여기서
> 사용하는 방식이 스마트 포인터. 이후에 객체 지향과 연결해서 ros 에서
> 사용가능.

# 15. 이해에서 수정할 핵심 2가지

## 수정 ①

> "개발자가 직접 메모리에 생성된 객체에게 포인터를 지정해야 한다."

→ **모든 객체에 포인터를 지정해야 하는 것은 아니다.**

``` cpp
Motor m;
```

처럼 포인터 없이 객체를 사용할 수 있다.

포인터는 객체를 **간접적으로 접근하거나 동적 객체의 수명 등을 다뤄야 할
때** 사용하는 도구다.

## 수정 ②

> "댕글러 포인트"

→ **댕글링 포인터(Dangling Pointer)**

``` text
객체 삭제
   ↓
포인터는 여전히 존재
   ↓
삭제된 객체의 주소를 가리킴
   ↓
댕글링 포인터
```

그리고 **메모리 누수와 댕글링 포인터는 서로 다른 문제**다.

# 16. 현재 단계에서 기억할 핵심 문장

``` text
스택
→ 수명이 스코프와 연결되어 자동 관리

힙
→ 동적으로 확보하는 메모리

참조
→ 기존 객체를 복사하지 않고 다룰 수 있는 별명

포인터
→ 메모리 주소를 저장하고 그 대상을 간접적으로 다루는 변수

메모리 누수
→ 메모리를 확보했지만 더 이상 제대로 관리/해제하지 못하는 문제

댕글링 포인터
→ 삭제된 객체를 여전히 가리키는 포인터

RAII
→ 자원의 수명을 객체의 수명에 묶어 자동 관리

unique_ptr
→ 단독 소유

shared_ptr
→ 공동 소유

ROS2
→ 위 개념들이 실제 C++ 로봇 프로그래밍에서 사용됨
```
