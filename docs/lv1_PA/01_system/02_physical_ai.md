# 임베디드, Edge AI, 클라우드의 연산 분담

## 핵심 요점

- **데이터는 발생 지점 근처에서 처리하고, 의미 있는 결과만 상위 계층으로 전송해요**
  - 고화질 영상 같은 원시 데이터를 모두 클라우드로 보내면 네트워크 대역폭 부족과 과도한 지연이 발생합니다

- **지연 예산과 데이터 전송량을 기준으로 작업 배치 위치를 결정해요**
  - 즉각성과 처리 무게의 균형을 맞춰 최적의 계층을 선택합니다

---

## 세 계층의 역할 분담

**임베디드(Embedded)**

마이크로초 단위의 즉각적인 제어가 필요한 작업을 담당해요. 모터 전류 제어처럼 센서와 실행 부분이 매우 가까워야 하며, 네트워크 통신 지연이 허용되지 않는 초저지연 작업이 여기 속합니다.

**Edge AI**

수십 ms 단위의 실시간 처리가 필요한 AI 추론을 수행해요. 객체 인식이나 이상 감지처럼 약간의 지연은 허용되지만 빠른 응답이 필요한 작업들을 Edge 기기에서 처리함으로써, 원시 데이터 대신 처리된 결과만 클라우드로 보냅니다.

**클라우드(Cloud)**

무거운 연산이 필요하지만 급하지 않은 작업을 담당해요. 모델 재학습이나 대규모 데이터 분석처럼 높은 계산 자원을 필요로 하되, 지연이 상대적으로 덜 중요한 배치 처리가 여기 적합합니다.

---

## 지연 예산의 중요성

지연 예산은 제어 시스템이 허용할 수 있는 최대 누적 지연 시간이에요. 긴급 제동처럼 10ms 이내의 반응이 필수적인 작업은, 클라우드 왕복 통신만으로도 수백 ms가 걸리기 때문에 로컬(임베디드)에서 처리해야 해요.

지연 예산이 짧을수록 하위 계층(임베디드에 가까운 곳)에서 처리하고, 지연에 여유가 있을수록 클라우드로 올려도 괜찮다고 생각하면 됩니다.

---

## 데이터 전송량의 역할

원시 센서 데이터(고해상도 영상, 고주파 센서 수치)는 전송량이 매우 크기 때문에 그대로 클라우드로 보낼 수 없어요. Edge AI에서 처리해 의미 있는 정보(탐지된 객체 좌표, 분류 결과 등)로 압축한 뒤 클라우드에 전송하면 네트워크 부담을 크게 줄일 수 있습니다.

---

## 헷갈리기 쉬운 지점

**"Edge AI도 즉각적인데, 왜 임베디드와 구분하나요?"**

임베디드는 **마이크로초·나노초 단위**의 물리적 제어가 목표이고, Edge AI는 **밀리초 단위**의 지능형 추론이 목표라는 점이 달라요. 제어 대상의 속성과 허용 지연 시간에 맞춰 선택하면 됩니다.
